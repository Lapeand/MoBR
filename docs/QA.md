# NutriAI 2.1 AI — проверки

## Автоматические проверки

18 unit-тестов проверяют локальные расчёты, разбор еды, CSV и интеграцию ИИ:

- пересчёт порции, сериализацию, несколько блюд, граммы/кг/мл и штуки;
- неоднозначные названия, неверную массу, различение сыра и сырников;
- Mifflin–St Jeor, рекомендации в пределах остатка всех БЖУ;
- экранирование CSV и защиту от формул;
- приоритет встроенного справочника над значениями модели: борщ 300 г + хлеб 40 г = 247 ккал;
- новый продукт: значения на 100 г масштабируются в Kotlin и помечаются как оценка ИИ;
- ответ на вопрос не создаёт пищевую запись;
- отказ от повреждённого/оборванного JSON, неизвестного ID, отрицательной порции, чрезмерного числа продуктов и неверных БЖУ;
- пустой текст с валидными продуктами получает стандартное пояснение;
- понятные сообщения для 401/402/403/429/503 без вывода необработанных сведений провайдера;
- точную модель, JSON Schema и ограничение истории шестью сообщениями;
- отсутствие фото и имени из профиля в запросе; слишком длинный ввод не вызывает сеть.

## Android без интернета

Перед прогоном выключаются Wi-Fi и мобильная сеть, включается авиарежим. Собственного API-процесса нет. Тесты явно выключают ИИ при подготовке, независимо от наличия ключа в APK.

1. Онбординг → борщ и хлеб → подтверждение → 247 ккал → закрытие Activity/ViewModel → чтение SQLite новым экземпляром → повторный запуск → удаление → 0 ккал.
2. Поиск гречки → черновик → пересоздание Activity → подтверждение → идемпотентность сохранения → CSV → очистка данных.
3. Локальное изображение → банан 100 г → импорт фото → подтверждение → удаление исходного файла → CSV → повторное чтение SQLite → фото и 89 ккал сохранены.
4. ИИ включён при недоступном соединении/ключе → понятная причина → локальный разбор → подтверждение → 247 ккал в SQLite.
5. Замена ключа → повторное открытие настроек → проверка зашифрованного хранения и сохранения переключателя режима.

CI выполняет unit-тесты, lint, сборку APK и пять локальных Android-тестов. Живой тест модели пропускается без явного параметра.

## Проверка настоящего OpenRouter

Опциональный Android-тест `liveAiParsesNaturalLanguageThenAndroidCalculatesAndStores` включается только параметром `liveOpenRouter=true`, с интернетом и ключом. Проверяет два запроса:

1. Естественная фраза «На обед съел тарелку борща 300 граммов и хлеб 40 граммов» → ответ именно Nemotron (не локальный fallback) → расчёт 247 ккал на телефоне → подтверждение и запись.
2. Вопрос об остатке калорий → ответ ИИ → нового черновика и лишней записи нет.

Команда приведена в README. Бесплатная модель зависит от доступности и лимитов провайдера, поэтому живой тест не блокирует обычную CI-сборку.

## Сценарий преподавателю

Установить APK и заполнить профиль. С интернетом отправить естественное описание обеда, показать ответ ИИ, источник данных и изменение порции, подтвердить запись. Открыть аналитику. Спросить об остатке калорий. В настройках выключить ИИ, включить авиарежим, добавить банан 100 г. Закрыть приложение и открыть снова: записи сохраняются. Показать рекомендации в профиле и экспорт CSV. Фото остаётся локальным вложением, автоматического распознавания нет. Голос отдельно проверяется на устройстве с локальной русской моделью Android.
