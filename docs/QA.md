# Проверка NutriAI

## Автоматические проверки

- Backend integration: auth/login, профиль и формула TDEE, запись только после подтверждения, идемпотентность, чтение и удаление только владельцем, графики по датам, CSV, рекомендации.
- Security / validation: неверный пароль, токен другого типа, одноразовое обновление сессии, отзыв refresh при выходе, неверный вес и даты, файл вместо фото, чужое фото.
- AI adapter: строгая JSON-схема, формат изображения, замена модельных значений справочными, маркировка оценочных значений. Провайдер в тесте заменён контролируемым ответом — реальный платный вызов не выполняется.
- Free quota: 20 сообщений; подмена даты дневника не обходит лимит; demo Premium доступен только при dev-флаге.
- Android unit: масштабирование всех нутриентов при изменении порции и десериализация реального контракта ответа.
- Android device smoke: регистрация → онбординг → «борщ 300 г, хлеб 40 г» → проверка → сохранение → 247 ккал в аналитике → пересоздание Activity.
- Alembic: первоначальная миграция и сравнение схемы с SQLAlchemy.

## Ручные сценарии перед защитой

1. Открыть API `/health`, затем Swagger `/docs`.
2. На телефоне зарегистрироваться, пройти профиль. Убедиться, что повторный запуск не требует нового входа.
3. В чате ввести `борщ 300 г, хлеб 40 г`. До подтверждения сумма дневника не меняется. Уменьшить порцию, проверить пересчёт, сохранить один раз.
4. Перейти в аналитику, посмотреть сумму, выбрать вчера и вернуться. Удалить запись и проверить уменьшение суммы.
5. Добавить ручное блюдо. Проверить защиту от пустых и отрицательных значений.
6. Выбрать фото, проверить превью и удаление вложения. С настроенным ключом проверить распознавание; без ключа должна быть понятная ошибка и возможность ручного ввода.
7. Проверить камеру и голос на реальном устройстве. Отмена системного окна не должна создавать запись. Голос должен только заполнить поле; отправка выполняется пользователем.
8. Изменить профиль: норма и рекомендации должны обновиться. Открыть детали обоих рецептов и добавить выбранный через подтверждение.
9. Сохранить CSV из настроек и открыть файл. Отключить сеть, перезапустить приложение: виден последний снимок, отправка не выдаётся за успешную.
10. Выйти; войти другим пользователем: дневник и история предыдущего не видны.

## Окружения, требующие отдельной проверки

Docker Compose с PostgreSQL / MinIO, внешний HTTPS/VPS, настоящий LLM/Vision ключ, Open Food Facts, камера и служба речи на физическом телефоне. Локальные SQLite и эмулятор не заменяют эти проверки. Проверку качества КБЖУ проводить на размеченном наборе блюд, а не считать приблизительные оценки эталонными.

## Результат локального прогона 19.10.2026

- Python 3.12: **6 тестов прошли**, один deprecation warning о будущем переходе тестового клиента Starlette с httpx на httpx2.
- Alembic: `upgrade head` и `check` прошли, расхождений схемы нет.
- Android JDK 17 / compileSdk 35: APK собран, **2 unit-теста прошли**, lint без ошибок (есть предупреждения об обновлении зависимостей, target API и стиле старых Preview).
- Эмулятор Android 17 / API 37: **1 сквозной тест прошёл**, включая сохранение блюда на реальном локальном API и восстановление после `Activity.recreate()`.
- Реальный платный LLM/Vision и Docker/VPS не запускались; в тесте адаптера используется контролируемый ответ провайдера.
