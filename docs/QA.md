# NutriAI 2.0 local — проверки

## Автоматические проверки

Unit-тесты Android проверяют:

- пропорциональный пересчёт КБЖУ при изменении порции;
- сериализацию сохранённой записи;
- разбор нескольких блюд, десятичной запятой, кг и количества штук;
- отказ от неоднозначной/неизвестной еды и неверной массы;
- различение сыра и сырников;
- расчёт TDEE и влияние пола/цели;
- рекомендации в пределах остатка калорий и всех БЖУ;
- CSV, экранирование запятых и защиту от формул.

Инструментальные тесты на Android без API проверяют:

1. У целевого APK отсутствует разрешение INTERNET. Онбординг → «борщ 300 г, хлеб 40 г» → подтверждение → 247 ккал → закрытие Activity/ViewModel → чтение SQLite новым экземпляром → повторный запуск → удаление записи → 0 ккал.
2. Поиск гречки в справочнике → черновик → пересоздание Activity → подтверждение → повторное сохранение с тем же request_id не дублирует запись → CSV → очистка данных.
3. Создание локального изображения → описание «банан 100 г» → импорт в закрытую папку приложения → подтверждение → удаление исходного фото → CSV на устройстве → повторное чтение SQLite и проверка сохранённого фото/89 ккал.

Перед UI-прогоном на эмуляторе выключаются Wi-Fi, мобильная сеть и включается авиарежим. Backend не запускается. В CI отдельный job `offline-ui` выполняет те же проверки на API 35.

## Сценарий показа преподавателю

1. Установить APK, включить авиарежим. Не вводить логин и адрес сервера — таких экранов нет.
2. Заполнить профиль и увидеть рассчитанную норму.
3. Написать `борщ 300 г, хлеб 40 г`, уменьшить/увеличить порцию, проверить КБЖУ, сохранить.
4. Открыть аналитику, посмотреть график, выбрать вчера и вернуться. Проверить отсутствие случайных данных.
5. Кнопкой книги найти продукт. Кнопкой + добавить собственное блюдо, введя КБЖУ на порцию.
6. Добавить фото с описанием еды. Проверить, что фото сохранилось в дневнике. Фото не распознаётся автоматически — это иллюстрация, расчёт по тексту.
7. Открыть профиль и рекомендации, добавить выбранное блюдо через подтверждение.
8. Из настроек экспортировать CSV. Закрыть приложение, остановить процесс и открыть снова: записи и профиль сохраняются.
9. Удалить запись, проверить уменьшение суммы. Сброс всех данных требует отдельного подтверждения.
10. Голос проверять отдельно на физическом телефоне Android 12+ с установленным локальным русским языковым пакетом. Если пакета/локального сервиса нет, приложение объясняет ограничение и сохраняет текстовый ввод.

## Границы проверки

Эмулятор не подтверждает наличие офлайн-речевой модели на каждом телефоне и работу физической камеры конкретного производителя. Автоматическое распознавание еды по фото и облачный ИИ не реализованы. Значения справочника приблизительные; для оценки точности нужен размеченный набор рецептов.

## Результат локальной проверки 19.10.2026

- JDK 17, compileSdk 35, эмулятор Android 17 / API 37.
- Авиарежим включён; Wi-Fi и мобильная сеть отключены; прежний тестовый backend остановлен.
- **10 unit-тестов прошли.**
- **3 инструментальных теста прошли**, включая повторный запуск, постоянную SQLite-базу, черновик, отсутствие дублей, удаление, локальное фото и CSV.
- `lintDebug` и `assembleDebug` прошли.
- `aapt dump permissions` готового APK: **INTERNET отсутствует**; разрешения только RECORD_AUDIO и внутренний DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION.
- Камера и голос на физическом телефоне требуют отдельной проверки конкретного устройства; локальная еда, дневник, расчёты и CSV от них не зависят.
- Дополнительно: все 3 UI-теста прошли с уменьшенным экраном 1080×1600. Проверки дневника явно прокручивают LazyColumn к записи и обратно к итогам, поэтому не зависят от видимости строки на конкретной высоте экрана.
